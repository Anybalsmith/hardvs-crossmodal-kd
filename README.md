# RGB → Event cross-modal distillation on HARDVS

Training code for the HARDVS experiments, on the full dataset (300 classes)
and on class subsets. The goal is to see whether distilling an RGB model into
an event-only student helps, compared with training the event model alone.

Three models are trained on each dataset. All of them are TSM ResNet-101 with
8 frames at 224×224:

| Config | Model |
|---|---|
| `tsm_r101_rgb_hardvs{50,100,300}.py` | RGB (APS frames) baseline, also used as the KD teacher |
| `tsm_r101_event_hardvs{50,100,300}.py` | Event (DVS frames) baseline |
| `tsm_r101_kd_rgb2event_hardvs{50,100,300}.py` | Event student distilled from the frozen RGB teacher |

`hardvs300` is the full HARDVS dataset. `hardvs50` and `hardvs100` are the
50 and 100-class subsets (seed 0). All three use exactly the same settings,
only the annotation files and the number of classes change. The
`*_hardvs300_session.py` configs train on the session-based re-split of the
full dataset (see [Other splits](#4-other-splits-optional)).

The KD loss is `CE + 0.3 · KL(T=4) + 0.5 · attention transfer` on the last
backbone feature map. Both KD terms are weighted per sample by the teacher
confidence. The student sees exactly the same data as the event baseline.
The teacher sees the RGB frames of the same recording, at the same time
steps and with the same crop and flip.

The code is a small plugin package (`hardvs_kd`) on top of the official
[mmaction2 v1.2.0](https://github.com/open-mmlab/mmaction2/tree/v1.2.0).

## Installation

Tested with Python 3.10, PyTorch 2.7.1 (CUDA 11.8), mmengine 0.10.7, mmcv-lite
2.1.0 and mmaction2 1.2.0.

```bash
conda create -n hardvs_kd python=3.10 -y
conda activate hardvs_kd

pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu118
pip install "numpy<2" mmengine==0.10.7 mmcv-lite==2.1.0 \
    opencv-python decord einops scipy matplotlib Pillow pandas

# mmaction2 must be installed from source in editable mode: the non-editable
# install of v1.2.0 is broken (missing mmaction.models.localizers.drn).
git clone --branch v1.2.0 --depth 1 https://github.com/open-mmlab/mmaction2.git
pip install --no-deps -e mmaction2

# This repository
git clone <this repo> hardvs-crossmodal-kd
cd hardvs-crossmodal-kd
pip install -e .
```

`mmcv-lite` is enough because TSM needs no compiled mmcv op. A full `mmcv`
in `[2.0.0, 2.2.0)` also works.

## Data preparation

All commands run from the repository root. By default the scripts and configs
expect this layout under `data/`, which git ignores:

```
data/hardvs/
├── rawframes/                 # HARDVS frames, can be a symlink
│   └── action_001/dvSave-2021_08_20_16_15_22/
│       ├── dvSave-2021_08_20_16_15_22_aps/00000000.png ...   # RGB
│       └── dvSave-2021_08_20_16_15_22_dvs/00000000.png ...   # events
├── train_label.txt            # HARDVS split lists: "path num_frames label"
├── val_label.txt
├── test_label.txt
└── annotations/               # generated by steps 1 and 2
```

```bash
mkdir -p data/hardvs
ln -s /path/to/HARDVS/rawframes data/hardvs/rawframes
ln -s /path/to/HARDVS/{train,val,test}_label.txt data/hardvs/
```

### 1. Per-modality annotation files

```bash
python tools/data/hardvs/make_hardvs_annotations.py
```

This writes `data/hardvs/annotations/{train,val,test}_label_{aps,dvs}.csv`,
one `action_XXX/<seq>/<seq>_{aps,dvs},<label>` row per recording. These files
are the annotations of the full dataset (`hardvs300` configs).

### 2. Class subsets (only for the `hardvs50` / `hardvs100` configs)

```bash
python tools/data/hardvs/make_hardvs_class_subset.py --num-classes 50 --seed 0
python tools/data/hardvs/make_hardvs_class_subset.py --num-classes 100 --seed 0
```

The classes are the first N of a seeded random permutation of the 300
classes, relabelled `0..N-1`. With the same seed, the 50-class subset is
included in the 100-class one. Each subset goes to
`data/hardvs/annotations/subsets/classes_<N>_seed<S>/`, along with
`classes.csv` (new label → original HARDVS class) and `subset_info.json`.

Expected sizes, which you can use to check that you got the same data:

| Dataset | train | val | test |
|---|---|---|---|
| full (`hardvs300`) | 64530 | 10734 | 32386 |
| `classes_50_seed0` | 11103 | 1847 | 5573 |
| `classes_100_seed0` | 22622 | 3761 | 11356 |


### 3. Event densities

Training uses event-density aware sampling. Among the frames that hold 95% of
the event mass, 6 frames are drawn weighted by density, and 2 frames are drawn
uniformly among the remaining ones. The RGB baseline uses the same sampling,
computed on the paired DVS recording. Validation and test use uniform
sampling, so only the training recordings need densities. The per-frame
densities (fraction of non-white pixels) must be computed once:

```bash
# Full training split: covers every subset
python tools/data/hardvs/precompute_event_density.py \
    --ann-files data/hardvs/annotations/train_label_dvs.csv \
    --data-root data/hardvs/rawframes --num-workers 8

# Or only the subsets, if you do not train on the full dataset
python tools/data/hardvs/precompute_event_density.py \
    --ann-files data/hardvs/annotations/subsets/classes_100_seed0/train_label_dvs.csv \
    --data-root data/hardvs/rawframes --num-workers 8
```

This writes a `.event_density.npy` file inside each `<seq>_dvs` folder. The
100-class subset covers the 50-class one. A re-split (step 4) moves official
val/test recordings into its training split: in that case, pass the three
files `data/hardvs/annotations/{train,val,test}_label_dvs.csv`. Valid caches are skipped, so the
script can be re-run safely. Without the caches, training still works but is
much slower, because the densities are recomputed every time.

### 4. Other splits (optional)

All scripts below read the annotation files of step 1 and write the same
`{split}_label_{aps,dvs}.csv` files, so any config can use their output.

**Session-based re-split** (`make_hardvs_splits.py`). In the official split,
the recordings of one class made in the same session (same day and hour) are
spread over train, val and test. Test recordings are therefore often near
duplicates of training ones (same subject, background and lighting), which
can make test accuracy optimistic. This script pools the three official
splits and re-splits each class so that every session goes to a single split:

```bash
python tools/data/hardvs/make_hardvs_splits.py \
    --out-dir data/hardvs/annotations/splits/session_hour_seed0
```

Options:

- `--session-level day` groups the recordings by day instead of by hour.
- `--mode random` splits the recordings of each class at random, without
  sessions, like the official split.
- `--ratios` sets the target share of recordings per split (default
  `0.6 0.1 0.3`, close to the official split).
- `--seed` changes which sessions go to val and test.
- `--ann-dir` points to a class subset to re-split it instead of the full
  dataset.

A class with only 2 sessions gets no validation recording. A class with a
single session is split at random. `split_info.json` lists these classes and
gives, for each split, the share of recordings whose session is also in
train. With the default settings (`session_hour_seed0`), you should get:

| Split | recordings | classes | session also in train |
|---|---|---|---|
| train | 62558 | 300 | 100% |
| val | 12012 | 269 | 1.0% |
| test | 33080 | 300 | 1.1% |

8 single-session classes are split at random. The
`*_hardvs300_session.py` configs train on this split.

**KD dev subset** (`make_hardvs_kd_dev_subset.py`, requires `pandas`). This
is a small subset for quick KD experiments. It keeps 56 classes picked from
earlier full-dataset KD runs: classes where KD helps or hurts most, hard
classes, short sequences, and classes where RGB is much better or worse than
events. Each class gets at most 60 / 10 / 30 recordings in train / val /
test, drawn within the official splits. Labels are remapped to `0..55`
(`class_mapping.csv`). Only recordings with both APS and DVS frames on disk
are kept.

```bash
python tools/data/hardvs/make_hardvs_kd_dev_subset.py
# -> data/hardvs/annotations/subsets/kd_dev_56cls_seed42/ (3360 / 560 / 1680 recordings)
```

The result depends on which frames are on disk. With the complete HARDVS
frames, no recording is dropped. An earlier version of this subset was built
from a partial extraction where 34 test recordings had no frames, so its test
split differs for one class (`action_144`, 18 recordings).

**Training on another split.** Add a config that inherits from the matching
full-dataset config and overrides the annotation files. Use the
`*_hardvs300_session.py` configs as a model. For a split with a different
number of classes, also set `num_classes`, as in the `hardvs100` configs.

## Training

Run every command from the repository root (configs use relative paths). The
settings are 1 GPU with batch 32. `auto_scale_lr` scales the learning rate
linearly with the total batch size (0.02 for 128, so 0.005 here).

```bash
# 1. Baselines
python tools/train.py configs/hardvs/tsm_r101_rgb_hardvs50.py
python tools/train.py configs/hardvs/tsm_r101_event_hardvs50.py

# 2. Distillation, with the best checkpoint of the RGB baseline as teacher
python tools/train.py configs/hardvs/tsm_r101_kd_rgb2event_hardvs50.py \
    --cfg-options model.teacher_checkpoint=work_dirs/tsm_r101_rgb_hardvs50/best_acc_top1_epoch_XX.pth
```

Replace `hardvs50` by `hardvs100` for the 100-class subset, or by `hardvs300`
for the full dataset. For multiple GPUs,
use `bash tools/dist_train.sh <config> <num_gpus>`. Keep in mind that the
total batch size, and therefore the learning rate, then changes.

The outputs go to `work_dirs/<config name>/` (or `--work-dir`):

- `best_acc_top1_epoch_N.pth` (KD: `best_acc_student_top1_epoch_N.pth`):
  the best validation checkpoint.
- `<timestamp>/<timestamp>.log`: the full log.
- `<timestamp>/test_metrics.jsonl`: test accuracy every 5 epochs and at the
  last epoch.

Metrics are `acc/top1`, `acc/top5` and `acc/mean1` (mean class accuracy).
For KD they are `acc/student_*` and `acc/teacher_*`.

Runs are seeded (`seed=42`, deterministic). `tools/train.py` sets
`CUBLAS_WORKSPACE_CONFIG` for that.

### Changing the student capacity

The student backbone can be changed from the command line. For example, a
ResNet-50 or ResNet-18 event student:

```bash
# ResNet-50 (2048 channels)
python tools/train.py configs/hardvs/tsm_r101_kd_rgb2event_hardvs50.py \
    --work-dir work_dirs/tsm_r50_kd_rgb2event_hardvs50 \
    --cfg-options model.teacher_checkpoint=<rgb ckpt> \
        model.backbone.depth=50 model.backbone.pretrained=torchvision://resnet50

# ResNet-18 (512 channels)
python tools/train.py configs/hardvs/tsm_r101_kd_rgb2event_hardvs50.py \
    --work-dir work_dirs/tsm_r18_kd_rgb2event_hardvs50 \
    --cfg-options model.teacher_checkpoint=<rgb ckpt> \
        model.backbone.depth=18 model.backbone.pretrained=torchvision://resnet18 \
        model.cls_head.in_channels=512
```

Use the same overrides on `tsm_r101_event_hardvs50.py` for the matching
event-only baseline. The attention-transfer loss only compares spatial maps,
so it works when student and teacher widths differ.

## Testing

```bash
python tools/test.py <config> <checkpoint> --work-dir <dir>
```

For a KD checkpoint, this reports both the student and the teacher accuracy.

## HRI subsets (command gestures)

Small subsets of HARDVS classes useful to command a robot or a drone by
gestures, trained with TSM-R50 (`configs/hri/`). The class lists are in
`tools/data/hardvs/hri_classes/`; `hri_classes_v4.csv` holds the 5 classes the
v1 baselines recognise worst (A072, A006, A073, A129, A106).

```bash
python tools/data/hardvs/make_hri_subset.py \
    --classes tools/data/hardvs/hri_classes/hri_classes_v4.csv \
    --out-dir data/hardvs/annotations/splits/hri_v4_official
```

Expected sizes for v4: 1354 / 226 / 679 (train / val / test). Class names are
read from `data/hardvs/HARDVS_300_class.txt` (from the HARDVS release) if it
exists.

| Config | RGB input |
|---|---|
| `rgb_r50_hri_v4.py` | raw APS frames (reference) |
| `rgb_r50_hri_v4_cadence.py` | half of the long training recordings reduced to 3-4 frames (`CadenceAugSampleFrames`), so that repeated frames stop being a class cue |
| `rgb_r50_hri_v4_clahe.py` | gray-world white balance + CLAHE on luminance (`ContrastEnhance`) |
| `rgb_r50_hri_v4_bgblack.py` | background set to black outside the clip-level person mask (`PersonMaskBackground`) |
| `rgb_r50_hri_v4_cadence3_test.py` | diagnostic, test only: every test recording reduced to 3 frames |

The black-background config needs the person masks, computed once with YOLO11x-seg
(`pip install ultralytics`):

```bash
python tools/data/hardvs/make_clip_masks.py \
    --ann-dir data/hardvs/annotations/splits/hri_v4_official --weights /path/to/yolo11x-seg.pt
```

Train a config, then test its best validation checkpoint with dumped predictions:

```bash
tools/hri/train_test.sh configs/hri/rgb_r50_hri_v4_cadence.py 0   # config, GPU id
```

`python tests/check_hri_pipelines.py` builds every HRI dataset and checks the
new transforms (no training).
